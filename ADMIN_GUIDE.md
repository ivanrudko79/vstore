# Руководство администратора VStore

## Важно: панель локальная

Публичный сайт размещён на GitHub Pages и не может безопасно выполнять серверный код. Поэтому панель владельца открывается только на компьютере владельца по адресу `http://127.0.0.1:4178`; это не публичная страница GitHub и не часть сайта, доступная посетителям.

## Первый запуск и GitHub

1. Установите Node.js LTS и Git. GitHub CLI доступен на компьютере владельца; если он ещё не распознаётся в старом терминале, закройте терминал и откройте его заново.
2. Один раз откройте PowerShell в папке репозитория и выполните `gh auth login`. Выберите `GitHub.com`, HTTPS и вход через браузер, затем завершите подтверждение на GitHub. Никому не отправляйте одноразовый код и не вставляйте токены в файлы проекта.
3. Убедитесь, что терминал открыт в папке репозитория `vstore`, и команда `gh repo view --json nameWithOwner -q .nameWithOwner` выводит `ivanrudko79/vstore`.
4. Дважды щёлкните `START_ADMIN.bat`. Панель откроется на `http://127.0.0.1:4178`. На экране обзора она покажет состояние Git, GitHub CLI, авторизации и выбранного репозитория.

GitHub Desktop может использоваться для обычных commit/push. Публикация IPA кнопкой в панели выполняет создание Release и отправку каталога самостоятельно через локальные Git и GitHub CLI. После push GitHub Actions собирает сайт и публикует его через Pages.

## Карточка и IPA

В панели выберите «Приложения» → «Добавить приложение». Заполните обязательные поля. ID — короткий уникальный ярлык для адреса и тега релиза, например `sber` (латиница, цифры и дефисы). Он отличается от Bundle ID. Черновик можно сохранить без IPA. Для публикации укажите источник, отметьте подтверждение права на распространение и выберите `.ipa`. Панель проверяет расширение, открывает архив и ищет `Payload/*.app/Info.plist`, считает SHA-256, размер и пытается извлечь Bundle ID, версию, имя и MinimumOSVersion.

Нажмите «Опубликовать». Панель создаёт GitHub Release с тегом `id-version`, загружает IPA как Release asset, сохраняет ссылку и SHA-256 в `data/apps.json`, затем делает commit и push. Ветка по умолчанию должна быть `main`. GitHub Actions соберёт и опубликует сайт. Если git push завершится неудачно, релиз уже создан: сохраните сообщённую ошибку, проверьте `data/apps.json`, затем отправьте изменения вручную.

Теги релизов уникальны: повторная публикация той же версии остановится, пока не будет увеличен номер версии. Загрузки IPA хранятся в GitHub Releases, а не в Git.

## Приложения и категории

Раздел «Приложения» позволяет добавлять черновики, редактировать и удалять записи. Удаление записи не удаляет уже опубликованный GitHub Release. Черновики не видны на публичном сайте. В разделе «Категории» можно добавлять, переименовывать и удалять категории; категорию с приложениями удалить нельзя — сначала назначьте этим приложениям другую категорию.

## Иконка и скриншоты

В форме приложения выбирайте иконку и скриншоты обычными файлами PNG, JPG/JPEG или WebP — URL вводить не нужно. Для каждого изображения действует лимит 5 МБ; можно добавить до 10 скриншотов. Панель проверяет тип изображения, сразу показывает предпросмотр и сохраняет файлы в `public/icons/` и `public/screenshots/`. При публикации приложения эти файлы отправляются в GitHub вместе с `data/apps.json`; GitHub Actions затем обновляет сайт.

Если сохранить только черновик, данные остаются в локальной папке проекта и не появляются на сайте. Не закрывайте форму до завершения загрузки изображений. Удаление карточки не удаляет уже выпущенный GitHub Release.

## Как сайт попадает в интернет

Публичный сайт уже размещён на GitHub Pages: <https://ivanrudko79.github.io/vstore/>. Исходники и JSON-каталог хранятся в репозитории `ivanrudko79/vstore`; IPA-файлы панель загружает в GitHub Releases. После публикации приложения панель делает commit и push, а GitHub Actions автоматически собирает сайт и обновляет Pages. Вручную загружать `dist/` через GitHub Desktop при обычной публикации не нужно.

Не публикуйте файлы без разрешения на распространение. SHA-256 подтверждает целостность относительно значения, но сам по себе не доказывает безопасность приложения.

# Безопасность и модель доверия

- Не добавляйте токены или пароли в публичный frontend, JSON или репозиторий. Панель вызывает официальный GitHub CLI; вход выполняется через `gh auth login`.
- Сервер панели bind-ится исключительно к `127.0.0.1:4178`. Не меняйте адрес на `0.0.0.0` и не проксируйте панель наружу.
- Панель проверяет IPA-расширение, структуру ZIP/IPA и считает SHA-256. Это базовая проверка целостности и структуры, не статический анализ и не подтверждение безопасности.
- Перед публикацией требуется явное подтверждение права на распространение, источник и валидный IPA.
- Не представляйте модифицированную сборку как оригинальную. Указывайте происхождение, изменения и права.
- GitHub Pages исполняет статические файлы; аутентификации, ролей или приватных данных пользователя в каталоге нет. LocalStorage темы — только визуальная настройка, не механизм авторизации.
- Не храните IPA в Git. Используйте Release assets и проверяйте действующие лимиты GitHub.
- Панель не имеет CSRF токена, но слушает только loopback. Не открывайте её недоверенным локальным пользователям. Не загружайте неизвестные архивы на рабочий компьютер.

## Пользовательские аккаунты в будущем

Для USER/ADMIN/SUPER_ADMIN и Google OAuth понадобится доверенный backend, база данных, провайдер OAuth, серверная проверка ролей, сессии и аудит. Защита страниц только на React или флаги в localStorage небезопасны. GitHub Pages можно оставить публичным frontend, если backend отдельно обеспечивает API и авторизацию.

Планируемые полномочия: GUEST — просмотр и скачивание; USER — профиль, избранное и история; ADMIN — приложения и категории; SUPER_ADMIN — пользователи, назначение/отзыв ролей, настройки и полный журнал аудита. Все эти права должны проверяться на сервере.
